# Bedrock Loom 渲染边界对抗式审查

> 审查基线：仓库当前内容、`min_engine_version` 1.21.0、`@minecraft/server` 1.14.0 声明和普通国际版客户端。除非路径卡另有说明，结论有效期截至 2025-02-01；客户端更新、实验性玩法设置、图形后端或资源包变化后必须重新探针。

## 1. 审计结论摘要

**当前平台在国际版“碰到”的是 R0 渲染数据，以及少量通过公开 Script API 提交的 R1 运行时对象请求；没有证据表明它获得 R2 渲染扩展或 R3 原生管线控制。** 资源包被游戏导入并绘制，不等于加载器拥有渲染回调、命令列表、顶点缓冲、Shader 或帧缓冲访问。

可重复验证的路径是：已声明资源的手持 attachable/geometry/动画控制器、白名单粒子、白名单音效、`onScreenDisplay` action bar，以及物品使用事件驱动这些资源。它们必须通过标准探针场景和真实客户端验收；当前仓库尚未保存自动视觉证据，因此证据状态为“仅仓库实现/待客户端验证”，不是“已验证”。

仅脚本层或资源层近似的能力：世界空间 UI、挂点对象、运行时换装、轨迹、范围面、路径线、billboard、屏幕后处理、相机抖动、FOV、描边、高亮。`CameraApi.pulse` 当前只是本地事件，不应宣传为画面效果。

在普通国际版官方边界下确定不能可靠承诺的能力：自定义 Shader、任意顶点/几何缓冲更新、帧缓冲后处理、绘制顺序/透明排序控制、深度测试控制、任意渲染层注册、原生相机 Hook、可靠骨骼程序化控制和任意动态纹理上传。限制来源是公开附加包/脚本接口没有对应授权扩展点；禁止以注入、逆向、私有符号或二进制修改填补。

## 2. 红 / 黄 / 绿清单

### 绿色：可进入 v1，但承诺必须限定为“资源或公开 API 结果”

- R0：资源包中的 geometry、attachable、贴图、动画、动画控制器、粒子、音效。
- R1 候选：物品使用事件、白名单粒子提交、白名单空间音效、action bar/toast。
- 单人优先：不依赖服务器的本地脚本和已打包资源。
- 只读观察：在 `getEntities` 实际可用并通过实验时，返回实体快照；不可用时返回 `unavailable`，不伪造“不存在”。
- BLSP/1：只请求已白名单、有限额的表现，不获得脚本或资源执行权。

### 黄色：experimental / platform-dependent，不进入稳定保证

- 动态实体挂点、世界空间 UI、运行时换装和材质变体。
- 粒子参数化、动画混合、骨骼程序化、轨迹和范围面。
- 相机事件、FOV、闪白、晕影和其他屏幕效果；当前国际版仅有事件或资源近似。
- 资源热重载、跨平台“同画面”、多人预测位置与透明叠加。
- `getEntities`、玩家实体骨骼名称和 UI 资源组合，因为版本、权限、实验设置和端形态需要实际探针。

### 红色：从稳定 API 移除或移入 custom-client-only

- “已接入渲染管线”“支持自定义渲染”“可任意修改画面”。
- 运行时替换 Shader、访问帧缓冲、提交任意命令或几何缓冲。
- 绕过签名、DLL 注入、函数 Hook、扫描私有符号、修改游戏二进制。
- 把网易接口直接翻译成国际版实现；把未来适配器说成可直接替换。
- “支持所有基岩平台”“跨平台效果一致”。

## 3. 渲染访问等级冻结规范

| 等级 | 精确定义 | 必须具备的证据 | 国际版当前结论 | 网易预留 | 定制客户端目标 |
|---|---|---|---|---|---|
| R0 内容表达 | 模组提供受支持的静态数据，游戏拥有导入、布局、绘制和生命周期 | 资源包校验、资源加载日志、标准场景截图 | 可达，证据待客户端黄金测试 | `platform-dependent` | 可达 |
| R1 运行时驱动 | 脚本通过公开接口创建/更新/销毁受支持对象，但不控制顺序、Shader、顶点或帧缓冲 | API 返回、对象计数、可见性与清理测试 | 部分可达：粒子、音效、屏幕 UI；模型/动画多为资源触发 | 未知 | 可达 |
| R2 渲染扩展 | 官方扩展点提供材质参数、几何、渲染层、UI 绘制、相机或后处理，仍不暴露私有结构 | 正式 SDK 文档、版本化扩展、最小实验和自动/视觉断言 | 未发现官方公开证据，不承诺 | 仅凭公开 SDK 和正式回复 | 需客户端所有者授权 |
| R3 原生管线控制 | 授权边界内访问渲染回调、命令、资源绑定、几何、Shader、帧缓冲或等价安全对象 | 正式授权、签名扩展、沙箱测试、崩溃隔离和 ABI 合约 | 不可达；仓库不得实现 | 不推断 | 需授权 SPI |

**等级判定规则：**“资源能显示”最多证明 R0；“脚本调用成功”最多证明提交到 R1 候选；只有观察到目标对象在固定场景的稳定画面结果，才记录 `first_visible` / `stable_visible`。任何成功返回不自动升级等级。

## 4. 真实数据流与停机点

### 4.1 本地脚本到画面

```text
模组脚本
  -> 公开 Client API（参数/权限/预算）
  -> international adapter（能力探测与降级）
  -> 已安装行为包脚本或资源包引用
  -> 官方资源解析/Script API 提交
  -> 游戏内部资源缓存与既有渲染器
  -> 画面
```

停机点：脚本不能插入逐帧渲染回调；不能读出私有渲染状态；不能控制透明排序、Shader、顶点或帧缓冲；资源缺失时不能假定有销毁事件；资源包热更换和缓存失效依赖客户端。

### 4.2 服务端表现请求

```text
可选 BLSP/1 -> 来源/版本/过期/幂等/权限/预算校验
  -> 白名单表现对象或资源引用 -> international adapter
  -> 同一本地 API -> 画面或安全降级
```

停机点：服务端不能发脚本、任意资源路径或玩法写入；断线、权限撤销和请求过期必须停止更新。服务器请求不提升渲染等级。

### 4.3 资源导入、缓存和卸载

```text
Geo/贴图/动画/材质定义 -> 导入工具 -> schema/路径/大小校验
  -> 资源包 -> 客户端资源加载 -> 缓存
  -> 资源引用计数（平台侧） -> 世界卸载/模组停用 -> 引用释放
```

停机点：普通附加包没有平台可控的 GPU 引用计数和强制卸载接口；`ResourceHandle` 只能表示平台索引，不得承诺立即回收。资源变更需重载/重进世界验证。

### 4.4 实体位置、骨骼和挂点

```text
实体官方位置/公开快照 -> 平台 tick 采样 -> 可选插值
  -> attachable/客户端实体资源引用 -> 相机剔除 -> 游戏既有绘制
```

停机点：不能保证每帧骨骼矩阵、不能保证骨骼名跨版本稳定、不能改变引擎剔除和排序；网络预测只能作为标记，不得冒充权威位置。

### 4.5 UI

```text
模组状态 -> 脏标记/节流 -> action bar 或资源包 UI 提交
  -> 游戏布局/DPI/焦点 -> 游戏 UI 绘制
```

停机点：当前示例只有 action bar；不能由 API 保证任意屏幕控件、焦点抢占、命中测试、布局重建时机或 UI 与世界深度关系。

### 4.6 未来 R2/R3 适配器

```text
同一公开 API -> capability 选择 -> 签名 Render Extension SPI
  -> 沙箱帧阶段/资源/几何/材质对象 -> 客户端渲染器 -> 画面
```

停机点：没有正式 SPI 时不得加载原生库；适配器必须声明 ABI、许可和能力，失败应回退 R0/R1 并隔离崩溃。

## 5. API 语义修订原则

每个创建/提交类 API 至少区分以下状态：

- `created`：参数通过并生成平台句柄，不代表资源已加载。
- `submitted`：请求已交给公开适配器，不代表画面可见。
- `first_visible`：探针在允许时间窗内第一次观察到目标。
- `stable_visible`：连续 N 帧和多个视角断言通过。
- `degraded`：使用近似或更低等级路径。
- `unavailable` / `not-supported` / `no-permission`：不得伪装成功。

位置来源必须标注 `authoritative`、`local-predicted`、`sampled` 或 `unknown`。销毁至少记录 `hidden`、`updates-stopped` 和 `release-pending`；世界卸载、死亡、传送、维度切换、断线和模组停用都要走统一清理。

并发仲裁固定为：资源 ID 由命名空间隔离；同一对象写入使用优先级 + 明确 owner；效果层使用 `priority`、`exclusiveGroup` 和确定性 tie-break；超过预算先拒绝新对象，再按远距/低优先级降级；不得依赖启动顺序。

## 6. 前两篇 API 的强制处置

| API/功能 | 宣称效果 | 目标 / 国际版当前 | 国际版证据与实现路径 | 自动测试 | 稳定性处置 |
|---|---|---|---|---|---|
| `ModelApi.register` | 注册模型 | R0 / R0 数据注册 | 写入索引；实际画面来自 attachable + geometry 资源；注册本身不创建实例 | ID、路径、资源缺失、黄金截图 | 稳定为 build-time/resource registry；不叫 runtime render |
| `MaterialApi` | 材质和 tint | R0 / R0 资源定义 | attachable/material 资源能否采用需客户端验证 | schema、纹理缺失 | 稳定但只承诺资源层；运行时材质覆盖降级 |
| `AnimationApi.play` | 播放动画 | R1 / experimental | 当前方法只生成播放描述，未调用逐帧渲染接口 | 状态确定性、资源存在、黄金截图 | experimental；资源控制器为稳定路径，动态混合不承诺 |
| `ParticleApi.emit` | 生成粒子 | R1 / R1 候选 | `player.spawnParticle`、白名单、距离和数量限制 | 计数、距离、粒子场景 | 稳定候选，证据待真实客户端 |
| `SoundApi.play` | 空间音效 | R1 / R1 候选 | `player.playSound` + sound definitions | 调用、距离、焦点降级 | 稳定候选；不属于渲染管线 |
| `ScreenUiApi.toast` | 屏幕提示 | R1 / R1 候选 | `onScreenDisplay.setActionBar` | 文本长度、TTL、重复清理 | 稳定但限 action bar，不承诺任意 UI |
| `WorldUiApi.mount` | 世界空间 UI | R1 / 不可用 | 当前代码明确返回 false 并诊断；无公开通用挂点绘制接口 | 必须返回 `not-supported` | 从稳定保证移出，保留 experimental/fallback |
| `InputApi` | 物品使用输入 | R1 / R1 候选 | `world.afterEvents.itemUse` 事件桥 | 焦点、重复订阅、注销 | 稳定；不等于低层键盘 Hook |
| `CameraApi.pulse` | 相机抖动 | R2 / 不可达 | 当前仅发本地事件，普通国际版无原生 Hook | 必须断言无画面承诺 | 改名/标注 `camera.request` experimental；默认 no-op |
| `EntityApi.attach` | 骨骼挂点 | R1 / R0/experimental | 仅保存描述，未绑定实际 attachable；资源层可预定义挂点 | 句柄、实体失效、视线场景 | 运行时 attach 移出稳定；资源挂点保留 |
| `EntityApi.observe` | 实体观察 | R1 / platform-dependent | `dimension.getEntities` 成功才报告 `ok`，异常报告 `not-supported` | unknown/unavailable、会话隔离 | 稳定只读契约，字段和频率 platform-dependent |
| `StorageApi` | 本地存档 | 非渲染 / 内存兼容 | 当前只有内存 Map，退出丢失 | 配额、迁移、清理 | experimental；持久化前不叫本地存档 |
| BLSP/1 | 服务端请求表现 | R1 / protocol-dependent | 白名单、预算、过期和幂等后复用本地 API | 恶意包、重连、撤销 | 稳定安全边界；不承诺对端可见 |
| 原生 Hook / Shader | 自定义渲染 | R3 / 不可达 | 无公开官方接口，仓库无实现 | 负向探针必须确认拒绝 | 从 v1 删除，移入 custom-client-only |

## 7. CapabilityProbe 结论

探测器只使用公开 API、资源加载结果和最小无副作用实验；禁止读私有内存、扫描函数签名、未定义行为或“看起来显示了”就永久缓存。完整接口和 JSON Schema 见 [CAPABILITY_PROBE.md](CAPABILITY_PROBE.md)。报告要记录发行形态、客户端/适配器版本、实验设置、设备、图形后端、画质、内存档位、资源指纹、实验结果、证据时间和失效原因。

缓存键至少包含：`clientBuild`、`adapterBuild`、资源包 SHA-256、实验玩法设置摘要、图形后端、画质档、设备能力档。更新客户端、资源包、画质或适配器时失效。探测阶段使用隐藏/零尺寸/离屏等官方允许方式；若无官方测试接口，必须标为 `unknown`，不能制造闪屏探针。

## 8. 自检与证据等级

- **A 接口自测试**：纯 JS 运行，不需要真实画面；覆盖参数、重复创建/销毁、权限、预算、异常隔离、固定时间步状态确定性和句柄泄漏。
- **B 客户端集成测试**：官方支持的测试环境或人工启动真实客户端；固定世界生成八个探针场景，采集对象计数、帧时间、内存、资源失败和清理结果。
- **C 视觉黄金测试**：固定种子、天气、时间、相机、分辨率和画质；采用像素/结构化容差比较。没有官方截图接口时只能人工验收，并在报告中标记限制；AI 目测不能替代断言。

证据状态只允许：`verified`、`documented-only`、`community-observed`、`pending`、`否定`。当前仓库的绝大多数视觉路径是 `pending`，因为仓库不包含国际版自动截图和官方渲染测试通道。

## 9. 授权路线

### 国际版

官方公开附加包/Script API 的当前上限按 R0/R1 设计。申请 R2/R3 必须向 Mojang/Microsoft 或正式 SDK 所有方提交：最小可复现包、数据流和权限模型、性能/崩溃预算、隐私与供应链方案、教育/创作/商业用例、平台覆盖、回滚与用户告知、自动化验收和兼容周期。在正式书面能力、版本化文档和测试通道到位前，仓库不得出现 DLL、注入器、Hook、私有符号、破解签名、Shader 替换器或二进制补丁。

### 网易

只依据公开 SDK、公开文档和正式商务/技术回复登记能力；“Mod SDK 渲染接口”与引擎内部管线分开记录。网易能力不能推断为国际版能力，适配器不能携带 SDK、游戏文件或平台二进制。

### 定制客户端

由客户端所有者提供签名的 Render Extension SPI。扩展可包含帧阶段、命令提交边界、资源生命周期、几何/材质/Shader、安全 UI、相机和后处理，但必须版本化、沙箱化、能力许可化、可撤销、无裸指针，并把插件错误隔离在宿主进程或受控 worker。草案见 [RENDER_SPI.md](RENDER_SPI.md)。

## 10. 供应链底线

原生适配器只能来自签名清单，清单绑定客户端构建、ABI、能力许可和 SHA-256；禁止从可写目录自动执行库。加载前校验签名和哈希，失败回滚到纯资源模式；第三方模块需要审核、最小权限、版本锁定和撤销列表。原生插件崩溃不得结束游戏，调试符号留在受控符号服务器，问题报告脱敏。用户可以查看已加载适配器、来源、签名、版本、哈希和权限。

## 11. v1 冻结承诺

**承诺：**资源包级 geometry/attachable/动画/粒子/音效、受限本地事件、action bar、白名单 BLSP 请求、能力探测报告、预算/权限/清理、明确降级和可审计证据。

**不承诺：**自定义 Shader、任意运行时几何/材质/纹理上传、后处理、渲染层/排序/深度控制、原生相机 Hook、跨平台同画面、网易等价实现、普通国际版 R2/R3。

在“不改二进制、不注入、不绕过平台限制”底线内，最优路线是：先把 R0 资源构建和 R1 公开 API 做成可验证产品；把每个高阶请求变成 capability-gated 的实验接口；同时以公开材料申请正式 R2/R3 扩展；授权只落在独立适配器和签名 SPI，不污染上层 API。
