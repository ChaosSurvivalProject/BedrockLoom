# 01 · 本机路径门禁记录

> 执行顺序第 1 步：**先检查本机路径，没有就停住等路径**。本文件是该步骤的完整记录，不是推测。

## 1. 实测时间与环境

- 时间：2026-11-06（会话内当前时间）
- 环境：`Linux 6.6.117 x86_64` / `Ubuntu 24.04.3 LTS`，**隔离云沙箱**
- 性质：这个环境**不是**作者持有 1.21.130 副本的 Windows / Android 机器，也无法访问其文件系统

这一点本身决定了门禁不会命中：用户所说的「本机已有副本」指作者自己的设备，而执行环境是另一个隔离系统。

## 3. 结论

> **本机无可解析的 1.21.130 底包 → 按规则停住。**

因此：

- **步骤 2（静态解析目录树 / manifest / renderer / materials / 字符串表）不执行**。没有目标时写出的任何「结构」「偏移」「符号」都是编造，属于主项目冻结定义里最严重的违规。
- 本仓库不包含 `material.bin` 样本、解析出的块、字符串表内容、提取资源。
- 唯一外部动作：`piston-meta` 官方版本清单**只读 JSON 查询**，见 [02](02-version-baseline.md)。**没有**下载任何游戏二进制、jar、apk、appx，也没有访问第三方论坛。

## 4. 继续所需的最小输入（若作者决定推进静态解析）

需要由作者在**自己的机器**上给出、并明确确认合法：

1. 一个**只含作者自己合法安装副本**的解包目录绝对路径，通过环境变量传入，例如：
   ```bash
   BLR_TARGET_DIR=/path/on/authors/own/machine/extracted node parser/layout.mjs
   ```
2. 该目录下不应包含从第三方重新分发的包；解析器不会联网、不会下载、不会写回。
3. 明确目标平台（Windows x64 / Android arm64）与 build 号，用于标注版本漂移风险。

解析器**会做什么**：只列文件名、大小、SHA-256、通用文件头魔数/块表统计、字符串长度分布计数。
解析器**不会做什么**：不输出任何样本内容、不推断私有符号、不硬写偏移、不修改源文件。

## 5. 即使给了路径，仍然停住的部分

必须提前说清，避免误解：

| 要求 | 给路径后是否执行 | 原因 |
| --- | --- | --- |
| 静态解析（目录树、头/块统计、字符串计数） | 可执行 | 只读、通用、不越界 |
| Hook 候选**分类表** | 可执行（仍标假设） | 分析记录 |
| 真实 `IDXGISwapChain::Present` detour / vtable patch / 注入实现 | **不执行** | 与「不绕签名/沙箱/反作弊」「不给完整改包成品」「禁止看起来能跑但越界的一键脚本」冲突 |
| 帧回灌到游戏交换链 | **不执行** | 属于改后客户端运行行为，超出「只写原创骨架」 |
| Java 未混淆包逻辑套用到基岩渲染 | **不执行** | 明确禁止项 |

也就是说：**路径解开的是「静态解析」，不是「注入成品」**。后者的边界不会因为有了路径就改变。
