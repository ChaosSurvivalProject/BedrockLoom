# 05 · Hook 候选表（风险分类，**不是实现清单**）

> ⚠️ 本表按「侵入度 / 风险」分 低·中·高，按 `Present` / `纹理绑定` / `相机更新` 三类组织。
> **全部条目 `status: unsupported`**，带 `host-private` / `research-hypothesis` / `version-drift-risk`。
> 机器可读版本：[`../hook/candidates.json`](../hook/candidates.json)；契约与桩：[`../hook/README.md`](../hook/README.md)。
> 本表**不提供**任何偏移、符号、vtable 索引、pattern 字节或安装代码。

## 1. 「低/中/高」的定义

分级维度是**风险与侵入度**，不是「实现难度」也不是「可行性」：

| 级别 | 含义 |
| --- | --- |
| 低 | 只读、进程外、不改变游戏状态；主要是公开图形调试/系统机制的记录 |
| 中 | 需要进程内只读观察点，或依赖平台特定运行时机制 |
| 高 | 涉及进程内代码路径改变、呈现链路介入、或可能触发平台完整性/反作弊机制 |

**可行性在本仓库一律为 `unsupported`**：级别低不代表我们会做，只代表风险相对小。

## 3. 每类的共同约束

- **不写私有符号表**：候选表只有抽象类别名，没有模块名、函数名、RVA、偏移、签名扫描字节。
- **不写安装逻辑**：`hook/IHookProbe.hpp` 只有纯虚接口；`hook/hook-contract.mjs` 的 `attach()` 恒返回 `unsupported`。
- **不写一键脚本**：没有「运行即注入」的入口；所有长任务返回七态结果，默认拒绝。
- **Android 空壳**：Android arm64 侧只登记「本机研究用空壳」这一事实，不提供 `.so`、不提供注入、不提供 apk 修改。
- **不伪装官方**：任何条目都不标 `stable` / `beta`，不写进主项目 API 总表，不合并 `main`。

## 4. 版本漂移因素（对全部条目生效）

| 因素 | 影响 |
| --- | --- |
| 客户端小版本 / build 差异 | 调用路径、模块布局可能整体变化 |
| Windows UWP/Store vs Android | 图形后端与进程模型完全不同，不可共用任何结论 |
| 驱动 / 图形 API 选择 | 呈现路径随设备与设置变化 |
| 实验开关（Vibrant Visuals / Deferred Technical Preview） | 渲染路径可能切换到另一套实现 |
| 平台完整性与反作弊更新 | 进程内观察点的可用性与合规性都可能改变 |

因此**任何在某一台机器、某一个 build 上得到的观察，都不能外推为 1.21.130 的通用结论**。这也是本仓库拒绝把「研究记录」升级为「Stable API」的核心原因。
