# 02 · 版本基线与官方元数据核实

> 区分「实测事实」「用户提供的目标」「已有记录」「未核实」四类，不混用。

## 1. 本次实测：piston-meta 官方版本清单（只读）

| 项 | 值 |
| --- | --- |
| 端点 | `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json` |
| 方法 | GET，**只读 JSON**；未下载任何 jar / 二进制 |
| 时间 | 2026-11-06 |
| HTTP | `200` |
| 响应大小 | `278772` 字节 |
| 版本条目数 | `922` |
| `latest.release` | `26.3` |
| `latest.snapshot` | `26.4-snapshot-7` |
| 命中 `1.21.11` | `1.21.11`、`1.21.11-rc1..rc3`、`1.21.11-pre1..pre5` |
| 命中 `1.21.130` | **无**（基岩版版本号不在 Java 版清单内，属正常） |

**结论 1**：Java `1.21.11` 在官方清单中真实存在，可作为「版本清单符号级对照」的锚点。
**结论 2**：官方当前主线已推进到 `26.x`。**任何 26.x 的文档、平台差异表、API 变更都不得作为 1.21.130 基岩版的证据**——主项目上一轮已排除第三方 `jaylydev` 页面里标注「as of v26.30」的平台差异表，此处沿用同一纪律。

## 3. Java 对照参考的合规用法

用户要求「Java 1.21.11_unobfuscated 官方启动器实验未混淆包，仅作符号/结构对照，不混用」，同时禁止「把 Java 未混淆逻辑直接套到基岩闭源渲染」。

本仓库的实际做法：

- ✅ 只记录 `1.21.11` 这个**版本标识符**存在于官方清单。
- ✅ 明确 Java 与基岩是不同代码库、不同渲染后端，不共享类/方法/管线结构。
- ❌ 未下载、未读取、未引用任何 Java 未混淆包或其类/方法/符号。
- ❌ 不把 Java 侧的任何结构推断套到 RenderDragon。
- ❌ 「官方启动器实验未混淆包」这一具体形态**本仓库未核实**，因此不作为任何结论的前提。

## 4. 基岩版 1.21.130 已有记录（沿用主项目，本次未重新联网）

以下来自主项目上一轮的官方来源核实，记录于 `../loom-v2/docs/06-international-capability.md`，供本研究对齐口径：

| 项 | 记录值 | 来源性质 |
| --- | --- | --- |
| 发布 | 2025-12-09 | 官方 changelog |
| 版本名 | 「群骑纷争」 | 官方 changelog |
| 协议号 | `898` | 官方 / 社区版本页 |
| 新增模块 | `@minecraft/server-graphics` | 官方 changelog |
| 该模块范围 | **仅** Vibrant Visuals 大气散射参数（`BiomeAtmospherics` 的 set/reset 系列） | 官方 changelog / Microsoft Learn |
| 不是 | 自定义 shader、帧缓冲、渲染层、几何提交、后处理 pass | 官方 changelog 措辞限定 |

**对本研究的意义**：官方新增的是「图形设置参数」，不是「渲染管线可观测接口」。所以即便在作者本机，能合法包装的仍是参数与公开 Script API；交换链/命令列表/相机矩阵属于另一层（A 层，假设）。
